# Фаза C — файлы в директ

**Goal:** Человек пишет комментарий с ключевым словом — и получает в директ PDF-чеклист,
а не только текст. Главный сценарий продукта начинает работать целиком.

**Spec:** `docs/superpowers/specs/2026-08-27-saas-comment-to-dm-design.md` (разделы 3, 5, 7)

**Отличие от планов фаз A и B:** здесь нет полных листингов кода. Планы A и B писались
для исполнения в отдельной сессии, где агент не видит репозиторий; этот план писался
и исполнялся подряд, поэтому фиксирует решения, сигнатуры и порядок, а код лежит
в репозитории. Для фазы D стоит вернуться к прежнему формату, если её будет
исполнять отдельная сессия.

## Global Constraints

Те же, что в фазах A и B. Дополнительно:

- Ядро в этой фазе **меняется** — впервые с начала SaaS-версии. Меняется ровно в трёх
  местах и только словарём, который не знает про платформы: `send_file` в `OutgoingAction`,
  `file_id` в схеме шага, перенос `file_id` в `buildScenario` и `renderStep`.
  Слова `instagram`, `meta`, `attachment` в `src/core/` не появляются —
  проверяет `tests/core/purity.test.ts`.
- Путь к файлу на диске **никогда не собирается из данных запроса** (S18): только из
  `user_id` и `stored_name`, оба сгенерированы нами.

## Ключевые решения

**1. Ядро знает `fileId`, но не знает `attachment_id`.**
Движок возвращает `{ type: 'send_file', fileId }` — ссылку на строку в нашей таблице.
Во что она превратится (идентификатор вложения Meta, публичная ссылка, что-то ещё
у TikTok) решает адаптер. Иначе платформенное понятие протекло бы в чистую логику.

**2. Выгрузка — один раз на файл, дальше по идентификатору.**
`files.attachment_id` заполняется при первой отправке и переиспользуется. Лид-магнит
уходит тысячам людей: без этого Meta выкачивала бы файл при каждой отправке, а сами
файлы пришлось бы держать доступными без авторизации (раздел 3 спеки).

**3. Текст и вложение — два действия, а не одно.**
Одно сообщение Instagram содержит либо текст, либо вложение. Шаг воронки с файлом
порождает два действия подряд: сначала текст, потом файл. В ядре для этого ничего
изобретать не пришлось — `step()` и так возвращает список.

**4. Умение отправлять вложения — отдельный интерфейс, а не метод `MessageSender`.**
У TikTok нет DM вообще, значит нет и вложений. `AttachmentSender` описывает выгрузку
и отправку по идентификатору; `InstagramAdapter` реализует оба интерфейса, а цикл
доставки сужает тип функцией-предикатом. Обязательный метод в `MessageSender` заставил
бы будущий TikTok-адаптер писать заглушку, которая всегда падает.

**5. Проверка файла — сигнатура, а не только заявленный MIME (S16).**
Заголовок `content-type` присылает клиент, и он ничего не гарантирует. Проверяются
три вещи: расширение по белому списку, заявленный MIME по тому же списку и первые
байты файла. Лимиты размера — из ограничений Meta: PDF 25 МБ, изображение 8 МБ.

**6. Имя на диске генерируется, присланное имя только показывается.**
`stored_name` — UUID с расширением из белого списка; каталог — `<FILES_DIR>/<user_id>/`.
Оба компонента пути наши, поэтому `../` в присланном имени никуда не ведёт (S18).

## Что фаза сознательно не делает

- **Не даёт клиенту загрузить файл.** Загрузка — это HTTP-форма, а формы и сессии
  появляются в фазе D. Здесь файл кладёт скрипт посева.
- **Не отдаёт файл по HTTP.** Маршрут скачивания — часть кабинета, там же и проверка
  владельца при отдаче (S18). Функции хранилища к этому уже готовы.
- **Не удаляет файлы.** Удаление осмысленно только вместе с кабинетом: надо решать,
  что делать с воронками, которые на файл ссылаются.

## Отклонения от плана при исполнении

- **`sendAttachment` принимает тип вложения отдельным аргументом.** В первом варианте
  теста тип был зашит как `file`. Платформа требует, чтобы тип при отправке совпадал
  с типом при выгрузке, иначе картинка, отправленная как документ, отвергается. Тип
  выводится из MIME функцией `attachmentKindOf` — она живёт в `adapters/types.ts`,
  потому что нужна и адаптеру, и циклу доставки.

- **`attachment_id` запоминается до отправки, а не после.** Выгрузка к этому моменту
  уже состоялась и уже оплачена трафиком; если запоминать после успешной отправки,
  любая ошибка на втором шаге заставит выгружать файл заново.

- **`Uint8Array.from(bytes)` вместо `Buffer` при сборке тела.** `Buffer` типизирован
  как `ArrayBufferLike`, а `Blob` принимает только `ArrayBuffer`, и `tsc` это ловит.
  Копия делается один раз на файл, а не на отправку.

- **`scripts/seed.ts` принимает четвёртым аргументом путь к файлу.** Иначе фазу нечем
  проверить руками: воронка с файлом создаётся только через конструктор, которого ещё нет.

- **Тест «токен уходит заголовком» использует ASCII-токен.** Заголовки HTTP —
  ByteString, кириллица в них не помещается, и падал тест, а не код. Настоящие
  токены Meta состоят из ASCII.
