# Запуск и надёжность — дизайн (фаза F, часть 2)

Дата: 2026-09-09
Статус: утверждён. Завершающая часть фазы F спеки `2026-08-27-saas-comment-to-dm-design.md`.

## 1. Задача

Подготовить сервис к реальной работе с Meta API и живыми клиентами:
1. Обработка 24-часового окна Meta (Instagram Messaging policy).
2. Троттлинг на клиента сервиса (S20) для защиты общих квот приложения.
3. Отображение неустранимых ошибок доставки в кабинете клиента (4xx, истечение окна).
4. Аудит гигиены логов (S4, S9).

## 2. Границы спеки

**Есть:**
- Проверка 24-часового окна при отправке сообщений в директ.
- Троттлинг отправки на уровне `user_id` (клиента сервиса).
- Запрос и страница/блок неустранимых ошибок доставки в кабинете клиента.
- Защита от утечки секретов и ПД в логах при сбоях отправки и обработки.

**Нет (сознательно):**
- Нет Message Tags / One-Time Notification (OTN): v1 работает в стандартном 24-часовом окне ответа на активность пользователя.
- Нет автоматического продления/напоминания о токенах через email (уведомления выходят за v1).

## 3. Архитектурные решения

### 1. 24-часовое окно Instagram
- В `conversations` уже есть `lastUserMessageAt`.
- При попытке отправить DM (`send_message` / `send_file`), если `now - lastUserMessageAt > 24 hours` и адресация идёт в существующий тред DM, действие помечается в `outbox` как неустранимо завершённое: `sentAt = now`, `failedReason = '24h_window_expired'`.
- Ошибки с кодом Meta API (`error_subcode: 2018001` / `code: 10 / 230` — "Outside allowed window") при отправке классифицируются как постоянные: не повторяются экспоненциально, а сразу фиксируются в `failedReason`.

### 2. Троттлинг на клиента сервиса (S20)
- Добавляется `THROTTLE_MAX_REPLIES_PER_CLIENT_PER_MINUTE` в `config.ts` (по умолчанию 100).
- Воркер доставки (`runDelivery`) перед выполнением действия проверяет лимит для `userId`. При превышении — переносит попытку (`nextAttemptAt = now + 10s`), не сжигая счётчик `attempts`.

### 3. Показ ошибок доставки в кабинете
- Запрос `listDeliveryErrors(db, userId, limit = 50)`: выбирает из `outbox` записи с `failedReason IS NOT NULL`.
- В веб-интерфейсе кабинета добавляется страница `/delivery-errors` и ссылка на неё (с индикатором при наличии ошибок).
- Тексты ошибок понятны человеку: «Истекло 24-часовое окно Meta», «Недействительный токен аккаунта», «Сообщение заблокировано платформой».

### 4. Гигиена логов (S4, S9)
- Никакие сырые ответы Meta с токенами или телами сообщений не логируются.
- Сериализаторы и обработчики ошибок в `worker.ts` и `adapters/instagram/sender.ts` логируют только `{ actionId, platform, httpStatus, errorCode }`.

## 4. Модель данных и запросы

Таблицы уже поддерживают этот функционал (`outbox.failedReason`, `conversations.lastUserMessageAt`).
Добавляются вспомогательные выборки:
- `listDeliveryErrors(db: AppDb, userId: string, limit?: number)`
- `dismissDeliveryErrors(db: AppDb, userId: string)` (при необходимости очистки).

## 5. Безопасность

- **S11**: Клиент видит ошибки доставки только своих автоматизаций (`userId` в `WHERE`).
- **S9**: `failedReason` содержит только безопасное описание категории ошибки, без полезной нагрузки и токенов.
- **S20**: Защита от исчерпания API-лимитов на уровне тенанта.
