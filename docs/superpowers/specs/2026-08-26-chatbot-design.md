# Мультиплатформенный чат-бот — дизайн

**Дата:** 2026-08-26
**Статус:** утверждён к реализации

## 1. Задача

Бот-воронка для **одного бизнеса**, отвечающий на входящие в Instagram и на
комментарии в TikTok по заранее описанным сценариям. Без AI: поведение
детерминировано конечным автоматом.

## 2. Границы (что в v1 есть и чего нет)

**Есть:**
- Instagram: приём Direct Messages и комментариев через webhook, ответ в DM,
  ответ на комментарий, авто-DM автору комментария.
- TikTok: опрос комментариев под видео Business-аккаунта, ответ на комментарий.
- Сценарии-воронки в YAML, правятся без правки кода.
- Передача лида живому оператору (`notify_operator`) в минимальном виде.

**Нет (сознательно):**
- Нет AI и LLM.
- Нет веб-панели — сценарии живут в git.
- Нет мультитенантности: один бизнес, один набор аккаунтов.
- Нет WhatsApp. Добавляется позже как один новый адаптер.
- Нет Redis — очередь и outbox лежат в основной БД.

## 3. Ограничения платформ (проверено 2026-08-26)

| Платформа | Приём событий | Что доступно |
|---|---|---|
| Instagram | webhook (push) | DM + комментарии; окно ответа 24 часа |
| TikTok | **только polling** | ответ на комментарии Business-аккаунта; **DM API отсутствует** |

Ключевое следствие: у TikTok **нет webhook на новый комментарий**, его
webhooks покрывают лиды, модерацию рекламы и заказы Creator Marketplace.
Поэтому один адаптер работает на push, другой на pull — и разницу обязан
скрывать адаптер, а не ядро.

Общего DM API у TikTok не существует. Business Messaging API доступен только
через партнёрскую программу, TikTok Shop Customer Service API — только для
переписки по заказам в Shop. Для одного бизнеса оба пути закрыты.

## 4. Архитектура

Принцип: **в `core/` не должно встречаться название ни одной платформы.**

```
src/
  core/        types, engine (чистая функция), matcher, scenario, throttle
  adapters/    instagram/, tiktok/
  storage/     schema (Drizzle), queries, crypto
  config.ts    единственное место чтения env
  server.ts    Fastify
  scheduler.ts таймер опроса TikTok
  worker.ts    очередь -> engine -> outbox
scenarios/*.yaml
```

### Два типа, на которых держится универсальность

Всё входящее приводится к `IncomingEvent`, всё исходящее — к `OutgoingAction`.
Ядро оперирует только ими и не знает, откуда событие пришло.

### Интерфейсы адаптеров

Не один интерфейс с опциональными методами, а три узких — чтобы компилятор
проверял, что именно реализовано:

```ts
interface MessageSender { platform; execute(action, ctx) }
interface WebhookSource extends MessageSender { parseWebhook(raw, headers) }
interface PollingSource extends MessageSender { poll(since) }
```

### Движок

```ts
step(scenario, state, event) -> { state, actions }
```

Чистая функция: ни `await`, ни БД, ни сети. Вся бизнес-логика тестируется
без интернета и без моков.

### Поток данных

```
Instagram: Meta -> POST /webhooks/instagram -> проверка подписи
           -> parseWebhook -> queue -> 200 OK (быстро)
TikTok:    таймер -> poll() -> dedupe -> queue
                                  |
           worker: queue -> load state -> step() -> save state
                   -> outbox -> sender -> adapter.execute()
```

HTTP-обработчик обязан ответить быстро: Meta отключает подписку у медленных
приложений. Поэтому обработка отвязана от ответа через очередь.

## 5. Обработка ошибок

| Проблема | Решение |
|---|---|
| Дубликаты (обе платформы доставляют at-least-once) | `processed_events` с UNIQUE по `dedupeKey` |
| Отправка упала (сеть, 5xx) | `outbox` + повтор с экспоненциальной задержкой |
| Платформа отказала осмысленно (4xx) | не повторять, пометить, уведомить оператора |
| Вне 24-часового окна Instagram | не ошибка сети, а бизнес-ситуация: решает сценарий |

## 6. Требования безопасности

Эти пункты — обязательные требования, а не рекомендации.

- **S1 (CRITICAL).** Подпись `X-Hub-Signature-256` считается HMAC-SHA256 от
  **сырых байт** тела на App Secret. Сравнение только `timingSafeEqual` с
  предварительной проверкой длины. Несовпадение -> `403` без тела.
  Fastify по умолчанию парсит JSON, поэтому raw body нужно сохранить до парсинга:
  `JSON.stringify(req.body)` не равен исходным байтам.
- **S2 (CRITICAL).** `hub.verify_token` в GET-хендшейке сравнивается тоже
  constant-time.
- **S3 (HIGH).** Instagram присылает вебхуки и на сообщения самого бизнеса
  (`message.is_echo`). Их обязан отбрасывать адаптер до очереди — иначе
  бесконечная петля самоответов.
- **S4 (HIGH).** Токены платформ никогда не попадают в логи, включая паттерн
  «залогировать весь объект ошибки». Refresh-токены TikTok ротируются, поэтому
  хранятся в таблице `platform_credentials`, зашифрованные AES-256-GCM на ключе
  из env. Точную политику жизни токенов Business API подтвердить в портале
  разработчика перед выкатом.
- **S5 (HIGH).** YAML парсится только безопасной схемой, результат валидируется
  Zod. Актуально на будущее: в день появления веб-панели сценарии станут
  недоверенным вводом.
- **S6 (MEDIUM).** Контекст диалога — `Map`, а не литерал объекта. Ключи
  приходят из сценария; `__proto__` в литерале даёт prototype pollution.
- **S7 (MEDIUM).** Текст пользователя обрезается по длине до матчинга.
  Регулярные выражения в триггерах v1 запрещены (ReDoS): только
  `exact` / `contains` / `starts_with`.
- **S8 (MEDIUM).** Троттлинг на контакт: не более N ответов в минуту.
- **S9 (MEDIUM).** Тела сообщений не логируются выше уровня `debug`.
  В БД лежат телефоны — это персональные данные.
- **S10.** Ошибка валидации env печатает только имена переменных, не значения.

**Проверено и неприменимо в v1:** XSS, CSRF, IDOR — нет фронтенда, нет сессий,
один тенант. Записано явно: **с появлением панели оператора IDOR становится
риском №1.**

## 7. Тестирование

- **unit** — движок и матчер: таблица «событие -> ожидаемые действия», без моков.
- **contract** — адаптеры против сохранённых реальных тел вебхуков в `fixtures/`.
- **security** — отдельные тесты на S1, S2, S3: испорченная подпись даёт 403,
  эхо-событие не создаёт исходящих действий.
- **integration** — фейковый адаптер + БД в памяти, прогон воронки целиком.

## 8. Открытое решение, оставленное владельцу

`core/matcher.ts` — функция `matches(trigger, userText)`. От неё зависит доля
клиентов, которых бот проигнорирует. Компромиссы: регистр (кириллица требует
`toLocaleLowerCase`), `contains` ловит ложные срабатывания («цена меня не
волнует» -> бот шлёт прайс на претензию), мусор вокруг («цена?», «  цена  »,
«цена 🙏»). Решение принимает владелец бизнеса, знающий свою аудиторию.
