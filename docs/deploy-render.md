# Деплой на Render

Пошагово, с местами, где обычно всё ломается. Конфигурация сервиса — `render.yaml`
в корне репозитория, её Render читает сам.

## Почему не Vercel

Там serverless: процесс живёт только на время HTTP-запроса. У сервиса внутри
`src/server.ts` два `setInterval` — разбор `event_queue` и опрос TikTok. На Vercel
комментарий записался бы в очередь и остался в ней навсегда: бот не ответил бы никому.
Плюс файлы клиентов пишутся на диск (`src/storage/files.ts`), а там файловая система
эфемерна. Render запускает обычный процесс и на платном тарифе даёт постоянный том —
поэтому код работает без единой правки. На free процесс тоже настоящий, но засыпает,
и тома нет: ограничения тарифа, а не модели (см. раздел ниже).

## Шаги

1. **Проверить видимость репозитория.** `Abulai09/InstaBot` сейчас публичный.
   Секретов в коде нет, но решение ваше — переключается в Settings репозитория.

2. **New → Blueprint** на Render, подключить репозиторий. Render найдёт `render.yaml`
   и создаст веб-сервис `insta-bot` на тарифе free — карту привязывать не нужно.

3. **Заполнить шесть секретов**, которые Render спросит (в `render.yaml` они помечены
   `sync: false`, значений там нет):

   | Переменная | Откуда брать |
   |---|---|
   | `DATABASE_URL` | строка Supabase целиком, с `?sslmode=verify-full&sslrootcert=./certs/supabase-prod-ca-2021.crt` |
   | `META_APP_SECRET` | настройки приложения Meta |
   | `META_VERIFY_TOKEN` | придумываете сами, тот же введёте в Meta на шаге 6 |
   | `CREDENTIALS_ENC_KEY` | **тот же, что локально.** Токены клиентов зашифрованы на нём |
   | `SESSION_SECRET` | тот же либо новый — новый разлогинит всех |
   | `PUBLIC_BASE_URL` | `https://insta-bot.onrender.com` (точный адрес виден после создания) |

4. **Накатить миграции.** Автоматически они не применяются — это отдельный шаг,
   и на сервере его делать нечем: `drizzle-kit` остался в `devDependencies`, а сборка
   идёт с `--omit=dev`. Прогоняются с любой машины, база-то облачная:

   ```bash
   # .env с боевым DATABASE_URL
   npm run migrate
   ```

   Если хочется автоматом при каждом деплое — на платных тарифах есть
   `preDeployCommand: npm run migrate`, но тогда сборку нужно менять на `npm ci`
   без `--omit=dev`, иначе `drizzle-kit` на сервер не приедет.

5. **Дождаться первого деплоя** и открыть адрес: должен встретить лендинг.
   Кабинет — по `/login`.

6. **Переключить вебхук Meta** на `https://<адрес>/webhooks/instagram`, тот же
   `META_VERIFY_TOKEN`. Handshake (GET) должен пройти сразу — он сравнивает токен
   constant-time (S2).

7. **Проверить живьём:** комментарий с ключевым словом под постом → ответ под ним
   и сообщение в директ. Если тихо — смотреть логи Render: строки воркера видны там же.

## Чего ждать от free-тарифа

Текущий `render.yaml` разворачивает сервис на free. Для проверки этого достаточно,
для клиентов — нет, и вот почему:

- **Сервис засыпает** примерно после 15 минут без запросов. Пока он спит, воркер
  не работает вообще: комментарии копятся в `event_queue`, ответы не уходят.
  Просыпается он только на входящий запрос, и первый вебхук Meta при этом ждёт
  холодного старта — а Meta отключает приложения, которые отвечают медленно.
- **Файлы живут до перезапуска.** Диска на free нет, `FILES_DIR` лежит рядом
  с кодом, и деплой его затирает. Прайс, загруженный вчера, сегодня может
  не отправиться: строка в таблице `files` останется, а байтов на диске уже нет.

Перевод на боевой режим — две правки в `render.yaml`: `plan: starter` и блок диска,

```yaml
    disk:
      name: files
      mountPath: /var/data
      sizeGB: 1
```

плюс `FILES_DIR: /var/data/files` вместо `./data/files`.

## Что сломается, если сделать иначе

- **Новый `CREDENTIALS_ENC_KEY`.** Токены доступа клиентов расшифровать станет нечем,
  каждый аккаунт придётся подключать заново.
- **Регион по умолчанию (Орегон).** База в `ap-southeast-2` (Сидней) и планируется
  в `eu-central-1`. Сервис во Франкфурте держит рукопожатие в десятках миллисекунд,
  в Орегоне — в сотнях, и страница кабинета снова станет двухсекундной.
